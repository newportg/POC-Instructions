Create an Instruction

Move freely between steps — fields change with the instruction type. The instruction is only accepted at Review.

SQLite cache: initialising…
Scope: information payload only, per instruction-information-requirements. No authority to act, KYC/AML, conflict checks, statuses or stage gates — those govern acting on the instruction, not describing it. Everything you enter is cached as a draft in a local SQLite database (lib/sql-asm.js, persisted to browser storage); nothing is accepted until you accept at Review.

      Step 5 Documentation — sections, hierarchy & connections

      Sections on this page

      Owning office — #owningOffice
      Select over the mock office directory: 10 offices across the UK, Spain, France, Germany and Poland, each showing its country. Choosing one sets the negotiator list and defaults the currency. Required.
      Assigned to — #assignedTo
      Negotiator select fed from the chosen office's list. Rebuilt whenever the office changes, because a negotiator belongs to one office. A draft saved with a negotiator that is no longer in the office's list keeps it as an (saved) option rather than dropping it. Required.
      Currency — #currency
      A default, not a fixed value. The office sets it only while you have not chosen one yourself: UK → GBP, eurozone (ES/FR/DE) → EUR, Poland → PLN. An explicit choice is flagged as user-set and survives later office changes.
      Fee basis, fee amount, expected revenue
      Commercial terms into state.terms. Fee basis is required; fee amount and expected revenue are optional. The fee payload (kf_fee, kf_feebasis, kf_currency) is only emitted once a fee amount exists.
      Notes — #notes
      Free text for anything exceptional about the matter.

      Step 6 Documentation — sections, hierarchy & connections

      Sections on this page

      Success banner — #successBanner
      Hidden until acceptance. Shows the generated reference in INS-{SEQNUM:6} format. Editing afterwards returns the draft to unaccepted and hides it again.
      Readiness rows — #readiness
      One row per step 1–5. Green when complete; red listing exactly which required fields are missing. Each row's “go to step” link jumps to that tab. Details reports “instruction type not selected” rather than green until a type exists.
      Accept error — #acceptError
      Lists the steps still short of their required fields if acceptance is attempted early.
      Review grid — #reviewGrid
      One read-only card per section — Type, Client, Property, Details, Terms — each with an edit link back to its step.
      Navigation — Back · Start over · Accept instruction
      Accept is disabled while any readiness row is red, and states why in its tooltip. Start over wipes the SQLite draft as well as the screen.
      Accepted record — #jsonCard · #jsonOut
      The payload frozen at acceptance: core kf_Instruction plus the type's specialised record, with a copy button.

      WIP Documentation — sections, hierarchy & connections

      Sections on this page

      View switch — #appNav · #view-create / #view-wip
      Moves between the wizard and this list. The badge on the WIP tab shows the live row count. The wizard keeps its draft while you are away.
      Grouping — #wipGroup
      Flat list, or grouped by Country, Branch (the owning office) or Negotiator. Each group header carries that group's own expected and fee subtotals.
      Filter — #wipFilter · #wipClear
      Free-text match across reference, type, client, country, branch and negotiator.
      Totals — #wipTotals
      Instruction count, total expected value and total fee, each broken down per currency. No exchange rate is applied, so a GBP total is never mixed with EUR or PLN.
      Table — #wipTable · #wipBody
      One row per instruction. Source is either ACCEPTED — pushed here by the Review tab — or MOCK — seeded fixture data.

      Connections

      MOCK MOCK_WIP — 15 seeded instructions across the five countries and ten offices. Seeded once, on first load; clearing rows does not resurrect them.
      LOCAL Acceptance feed — accept() on Step 6 writes a flat row here from the frozen payload. Re-accepting the same reference replaces its row rather than duplicating it.
      LOCAL Draft cache — rows live in a wip table in the same SQLite database as the draft (lib/sql-asm.js), with a JSON fallback in browser storage. No network.
